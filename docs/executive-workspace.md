# Executive billing workspace

- **Executive insights** (`/insights/`): completed-day MTD, conditional month-end run-rate, equal-length previous-month comparison, and top customer/account/service cost movements. Regional investigation opens the existing scoped Cost Explorer; the daily ledger does not store regional costs. Coverage and import freshness are shown separately. Forecasts are withheld for stale, failed, paused or incomplete feeds.
- **Budgets & savings** (`/optimization/`): Flentas limits, consumption, remaining amounts, projected breaches, missing account limits and recorded alarm history. Parent and child budget scopes are not summed. Savings reviews rank observed account-service spend and suggest utilization, storage, rightsizing or commitment investigations. Estimated savings remain unavailable without the required usage/pricing evidence; no resources are changed and no new AWS permissions are requested.
- **Billing reconciliation** (`/reconciliation/`): download the four-column template, select a customer/month/currency and upload CSV or single-sheet XLSX. Account IDs must remain 12-digit text. Uploads are limited to 2 MB and 5,000 rows, validated against authorized customer/account history, processed in memory and not persisted. Formulas, nonfinite values, wrong periods/currencies and duplicate accounts are rejected. Complete AWS amounts within 0.01 currency units match; incomplete data never passes as reconciled. Tax, markup, credits and invoice adjustments can legitimately explain differences.
- **Monthly Excel reports** (`/reports/monthly.xlsx`): executive, account and service-change worksheets, with coverage-aware comparisons, formatted amounts, frozen headers, wrapped explanations and account IDs stored as text. Spreadsheet values cannot execute formulas. Select the reporting month/customer through the reconciliation page.
- **My access** (`/my-access/`): effective customer/account scope, MFA enrollment and session revocation. Portfolio administrators can select **Create customer login** to prefill a read-only viewer for one customer, then review the existing user form before saving. Each user receives their own login and enrolls MFA. Existing customer-role external invitation/readiness gates are preserved; no customers, identities or access grants are automatically created by this release.

Every view uses the existing account/customer authorization boundary and web database permissions. Read-only invoice previews restore read scope for POST without granting write capability. Account-restricted insights use generic billing-feed labels to avoid exposing a shared payer's identity. PostgreSQL runtime tests cover all new pages and report exports. No schema migration is required.
